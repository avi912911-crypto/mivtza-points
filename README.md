# מערכת נקודות המבצע

מערכת אינטרנט לעדכון נקודות תלמידים: הזנה יומית לפי מורה בוקר ואחה"צ, דשבורד, כרטיס תלמיד וממשק ניהול.

## הרצה מקומית

דרוש Node.js 22.13 ומעלה.

```bash
npm install
npm start
```

האתר עולה בכתובת http://localhost:3000. בכניסה הראשונה המערכת מבקשת ליצור חשבון מנהל (או שהוא נוצר מראש מ-`ADMIN_PASSWORD`).

## הגדרות סביבה

| משתנה | משמעות | ברירת מחדל |
| --- | --- | --- |
| `PORT` | פורט השרת | 3000 |
| `DATA_DIR` | תיקיית מסד הנתונים והגיבויים | תיקיית ה-Volume של Railway, אחרת `./data` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | יצירת משתמש מנהל מראש (לא חובה) | ללא: המבקר הראשון יוצר את המנהל |

## העלאה ל-Railway

1. מחברים את מאגר ה-GitHub לפרויקט חדש ב-Railway (New Project → Deploy from GitHub repo).
2. מוסיפים Volume לשירות (נקודת עגינה `/data`). המערכת מזהה אותו לבד.
3. ב-Settings → Networking לוחצים Generate Domain כדי לקבל כתובת.
4. נכנסים לכתובת ויוצרים את חשבון המנהל.

## קו טלפון לבדיקת נקודות (ימות המשיח)

בהגדרות המערכת (מנהל) מופיעה כתובת עם קוד סודי. מגדירים אותה בשלוחת API בימות המשיח (`type=api`, `api_link=<הכתובת>`).
התלמיד מזוהה לפי מספר הטלפון שממנו התקשר (שדה "טלפון" בכרטיס התלמיד), ושומע כמה נקודות צבר. בסוף ההודעה השיחה מתנתקת.

## נוכחות יומית

בהגדרה "נוכחות יומית פעילה" (בעמוד "זיהוי פנים") המורה מסמן בסעיפים היומיים באילו ימים התלמיד נכח (נוכח / איחר / חסר), והספירה השבועית שבה מחושבות הנקודות מתעדכנת לבד. "איחר" לא מקבל נקודות. כשההגדרה כבויה המורים מזינים מספר לשבוע כמו קודם. בהפעלה, מספרים שהוזנו פוזרו על הימים הראשונים של השבוע, והנקודות לא משתנות.

## עמדת זיהוי פנים

עמוד "זיהוי פנים" (מנהל) קובע מי רשאי, רושם פנים (5 צילומים, נשמרת רק טביעה מספרית), שעות רישום לכל סעיף ומשפטי משוב. הטאבלט פותח את `/kiosk#<קוד>`, והזיהוי רץ בדפדפן (face-api). כל עוד נוכחות יומית כבויה העמדה במצב ניסיון: הרישומים נשמרים ומוצגים, אבל הנקודות לא משתנות.

## מבנה

- `server.js` – שרת Express וכל ה-API.
- `db.js` – מבנה מסד הנתונים (SQLite מובנה ב-Node), ערכי ברירת מחדל וגיבוי יומי.
- `public/` – הממשק (HTML, CSS, JavaScript ללא שלב בנייה).
